Was ist eine Domain?

Ein eigenes Objekt im Schema. Es beschreibt, wie ein fachlicher Wert aussieht: Datentyp, Regel, Vorgabewert, Anzeige und Sortierung. Spalten verweisen darauf, statt die Regel selbst zu tragen.

Ohne Domain

create table filiale (
  plz varchar2(5)
    constraint chk1_filiale check (regexp_like(plz, '^[0-9]{5}$'))
);
create table lager (
  plz varchar2(5)
    constraint chk1_lager check (regexp_like(plz, '^[0-9]{5}$'))
);

… und in jeder weiteren Tabelle noch einmal.

Mit Domain

create domain plz_dom as varchar2(5)
  constraint chk1_plz_dom check (regexp_like(value, '^[0-9]{5}$'));

create table filiale (plz domain plz_dom);
create table lager   (plz domain plz_dom);
  • Die Regel steht an genau einer Stelle.
  • Die Datenbank kennt die Bedeutung der Spalte, nicht nur ihren Datentyp.
  • Werkzeuge wie APEX lesen die Domain aus dem Data Dictionary.

Seit SQL-92 im Standard

Mit Domains: Oracle Rdb, InterBase, Firebird (2002), PostgreSQL 7.3 (2002), SQL Anywhere, HSQLDB 2.0 (2010), H2, CockroachDB und Oracle Database seit 23ai (2024) – dort zusätzlich mit Display, Order und Annotations.

Ohne: SQL Server, MySQL, MariaDB, Db2, SQLite.

Der Bauplan einer Domain

Einspaltige Domain

create domain <name> as <datentyp>
  [strict]
  [default <ausdruck>]
  [not null]
  [constraint <name> check (<bedingung mit value>)]
  [display <ausdruck>]
  [order <ausdruck>]
  [annotations (...)];

Enum-Domain

create domain <name> as enum (
  <name> [= <kurzform>] = <wert>, ...
)
  [annotations (...)];

Das Stadtwerk – das Datenmodell

Ein erfundenes Stadtwerk: Kunden, Lieferanten, Mitarbeiter, Fahrzeuge, Leitungen, Störungen. Über Jahre von verschiedenen Teams gewachsen – und genau so sieht es aus.

Rot sind die Spalten, deren fachliche Regel jedes Mal anders umgesetzt ist

  1. Status der Störung stoerung
    Eine Werteliste im Check chk1_stoerung, aber mit unterschiedlichen Schreibweisen: status in ('neu', 'NEU', 'in Arbeit', 'erledigt', 'Erledigt')
  2. Spannungsebene leitung
    Freitext, 14 Schreibweisen für 3 Ebenen.
  3. Kennzeichen fahrzeug
    Mit und ohne Bindestrich, mit Leerzeichen an allen Stellen, klein geschrieben.
  4. Email kunde, lieferant, mitarbeiter
    Bei Kunden ein strenger Check per RegEx chk1_kunde, bei Lieferanten ein laxer per like chk1_lieferant mit Trigger tbiu_lieferant, bei Mitarbeitern gar keiner.
  5. Telefonnummer kunde, lieferant
    Ungeprüft, von „0911/234567“ bis „folgt“.

Eine Werteliste als Domain

Ohne eigene Werte nummeriert Oracle nach der Position in der Liste. Wer später einen Namen dazwischen einfügt, verschiebt die Bedeutung der gespeicherten Zahlen. 
create domain status_enum as enum (neu, in_arbeit, erledigt);
-- neu = 1, in_arbeit = 2, erledigt = 3

create domain status_enum as enum (neu, in_pruefung, in_arbeit, erledigt);
-- gespeicherte 2 heißt jetzt in_pruefung statt in_arbeit

Den Status umstellen

Der alte Check in der Tabelle stoerung: 
constraint chk1_stoerung check (status in ('neu', 'NEU', 'in Arbeit', 'erledigt', 'Erledigt'))

Die Reihenfolge

Display und Order lassen sich ändern – die Werteliste nicht.

Spannungsebene mit Kurzform

Jede Kurzform ist eine eigene Zeile: für eine Werteliste filtern.

Kennzeichen

[A-Z] hängt an der Sortierung der Sitzung: Mit NLS_SORT = GERMAN trifft es auch Kleinbuchstaben. [[:upper:]] verhält sich immer gleich.

Dieselbe Regel, dreimal anders und an drei verschiedenen Stellen

Strenger Check, laxer Check mit Trigger, gar nichts – „das prüft die Anwendung“.

Was durchgerutscht ist

Die Email-Domain anlegen und an die Kunden hängen

Die Kunden sind schon sauber; Lieferanten und Mitarbeiter kommen erst bei der Migration dran.

Was die Domain kann

Sortiert wird erst nach Domain, dann nach Name: anna.schmidt@example.com wird zu example.com anna.schmidt.

Anhängen scheitert: Wer stört?

Das Anhängen prüft jede vorhandene Zeile, die Meldung nennt weder Constraint noch Domain. domain_check findet die Störenfriede, bevor etwas angehängt ist.

Aufräumen

Sauber machen heißt nicht nur Regex: Den Rest entscheidet ein Mensch.

Jetzt passt es

Altlasten entfernen

Eine Domain prüft und zeigt an – gespeicherte Daten verändert sie nicht.

Jetzt prüft nur noch die Domain

Was Oracle schon mitbringt

Erst nachsehen, dann selbst bauen – aber die Regel prüfen.

Telefonnummer (vordefiniert)

Die Regel erlaubt nur 1 bis 16 Ziffern, davor höchstens ein Plus. Leerzeichen, Schrägstrich, Klammer, Bindestrich oder Punkt lassen sie scheitern; null besteht.

phone_number_d bringt Oracle im Schema SYS mit. Die Domain setzt das Format durch. Vereinheitlichen muss man vorher selbst – und 0911 zeigt: Die Regel ist zu schwach.

Irreführende Fehlermeldungen

Domains und PL/SQL

PL/SQL kennt keine Domains: weder Variablen noch Parameter, %type liefert nur den Grundtyp. domain_check geht nur über SQL.

So wurde sie angelegt

create domain stoerung_status_enum as enum (
  neu       = 'neu',
  in_arbeit = 'in Arbeit',
  erledigt  = 'erledigt'
)
annotations (description 'Bearbeitungsstand einer Störung');

Das Data Dictionary liefert nicht die ursprüngliche Anweisung – die create-Anweisung gehört ins Repo.

force oder force preserve

force

Der geerbte Check verschwindet. Bis zum neuen Anhängen ist die Spalte ungeschützt.

force preserve

Der Check bleibt als gewöhnlicher Constraint SYS_C… stehen.

Die Falle mit preserve

Der bewahrte alte Check kennt storniert nicht – erst wenn man ihn löscht, ist man fertig.

Vor dem DROP DOMAIN

Nach dem Umbau

Domain oder Nachschlagetabelle?

Enum-Domain

  • stabile, technische Wertelisten: Status, Spannungsebene
  • Änderung nur durch Neuanlegen
  • keine Zeilen, auf die verwiesen wird, keine Joins

Tabelle mit Foreign Key

  • Werte haben eigene Eigenschaften
  • Werte kommen im Betrieb dazu
  • Pflege über die Anwendung

Das Kleingedruckte

Non-strict prüft keine Längen

Eine Domain mit 320 Zeichen hängt an einer Spalte mit 200 – die Länge der Domain ist dann nur Dokumentation. strict verlangt exakt denselben Typ.

Eine einzelne Spalte lösen

alter table … modify … drop domain scheitert mit ORA-02000. Es geht nur über drop domain … force für alle Spalten.

Namen

Eine eigene email_d verdeckt die mitgelieferte SYS.EMAIL_D. Deshalb enden unsere Domains auf _dom.

Werkzeuge

IDEs markieren gültige Domain-Syntax oft als Fehler. Die Datenbank entscheidet.

Fünf Dinge zum Mitnehmen

  1. Eine Regel einmal als Domain festlegen und überall anhängen.
  2. Erst mit domain_check die Störenfriede suchen und aufräumen, dann anhängen.
  3. Bei Enum-Domains die Werte selbst angeben und die create-Anweisung im Repo aufbewahren.
  4. Nach force preserve die alten Checks löschen.
  5. PL/SQL kennt keine Domains: domain_check über SQL aufrufen.
